# AI-codegen smell audit: 2026-08-06

## Summary
- Commit audited: `316a2ec4c80ceab8ebde8b946ef4bf0457393057` on branch `main`
- Scope: `src/song_generator/` (27 modules) plus `tests/` for the checks that apply there (swallowed-errors, mirror-tests, phantom-todos)
- Total findings: 10 (critical: 0, major: 2, minor: 6, nit: 2)
- False-positive log applied: no, first run

Four of the ten checks came back clean: defensive-checks-for-impossible-cases,
paraphrase-comments, phantom-todos and over-typed-primitives. The codebase is a
poor host for most of these smells. Naming is domain-dense throughout, every
optional parameter is annotated `| None`, comments carry measurements and past
bugs rather than restating code, and there is not a single TODO comment marker
or `typing` import in the package. The comment culture (a broad `except`
explains why it is broad, for example `set_aside.py:101`) did most of the
immunising work during this audit.

Per project convention, `config.py` and its prose comments were excluded from
the stylistic and comment checks, guards documented in `AGENTS.md` (filename
sanitisation of measured values, ASR pinned to temperature 0.0, the libsndfile
PEAK chunk) were treated as legitimate, and the standalone tools
(`set_aside.py`, `recut_bank.py`, `hunt.py` and similar) were not flagged for
being single-purpose.

### Major

- [src/song_generator/arrange.py:488](../../src/song_generator/arrange.py#L488): `int(meta["seed"])` failure silently becomes `seed = 0` with no log, no comment. (swallowed-errors)
  This directly contradicts `parse_text`'s own docstring (`arrange.py:412`), which says the parser is strict about anything that would change what is sung without saying so. The three neighbouring handlers in the same function all raise `ArrangementError` with a line number. The seed is load-bearing: `arrange.py:628` records it precisely so an arrangement can be replayed, and `:632`/`:700` reseed `random.Random` and name the log file from it. A hand-edited or corrupted `# seed` line replays a different arrangement under the same filename with no diagnostic. Suggested: `raise ArrangementError(f"seed must be a whole number, got {meta['seed']!r}")`.

- [src/song_generator/batch.py:38](../../src/song_generator/batch.py#L38) / [src/song_generator/mine_words.py:108](../../src/song_generator/mine_words.py#L108) / [src/song_generator/separate_hq.py:96](../../src/song_generator/separate_hq.py#L96): `expand()` glob-expansion helper exists three times. (duplicated-helpers)
  The `batch.py` and `mine_words.py` copies are verbatim (same name, signature, control flow, warning string, dedupe). The divergence risk is not hypothetical: the inline third copy in `separate_hq.py:96` already dropped the "nothing matched" stderr warning and the resolve-based dedupe, so the same CLI gesture behaves differently depending on which entry point is invoked. Upgraded from the minor default because all three sit on shipped entry points and one has already diverged. Suggested: one copy in `util.py` (which already hosts `slugify` and `work_dir_for`), called from all three.

### Minor

- [src/song_generator/label_words.py:62](../../src/song_generator/label_words.py#L62) / [src/song_generator/precheck.py:97](../../src/song_generator/precheck.py#L97): the fuzzy-match scoring core (`SequenceMatcher` ratio plus the `len(heard) >= 4` prefix boost to `0.75`) is duplicated between `best_target` and `match_single`. (duplicated-helpers)
  `precheck.py` already imports `normalise` from `label_words`, so the copy is not an isolation choice. Retuning the matcher in one stage silently leaves the other stage on the old rule, and both stages score the same clips. The wrappers legitimately differ (candidate pool, return shape); only the per-target scoring line group needs extracting.

- [tests/test_docs.py:166](../../tests/test_docs.py#L166): `except (UnicodeDecodeError, FileNotFoundError): continue` in the attribution-enforcement test. (swallowed-errors)
  Skipping undecodable binaries is clearly the intent, but bundling `FileNotFoundError` means a `git ls-files` entry missing from the working tree is silently dropped from an enforcement test, which can then report zero offenders while scanning fewer files than it claims. Downgraded from the major default because it is a coverage gap in a test, not a swallowed production write. Suggested: split the handlers and comment the binary skip.

- [src/song_generator/standardize.py:439](../../src/song_generator/standardize.py#L439) and [:492](../../src/song_generator/standardize.py#L492): `info` for a value whose declared type is the domain dataclass `Level`. (generic-names-in-domain-context)
  At `:492` it is the fourth element of a four-tuple whose three siblings (`audio`, `updated`, `trim`) are all named concretely, and its fields (`lufs_before`, `gain_db`, `ceiling_limited`) are only discoverable by scrolling to the producer. `standardize.py` is named in `docs/ARCHITECTURE.md`. Suggested rename: `levelling`.

- [src/song_generator/doctor.py:193](../../src/song_generator/doctor.py#L193): `data` for the parsed `analysis.json` payload, live for about ten lines (`data["notes"]`, `data["duration_s"]`, `data["tempo_bpm"]`). (generic-names-in-domain-context)
  The payload has a name the glossary and the whole `analysis.py` stage use. Marginal because `analysis_path` sits on the line above. Suggested rename: `analysis`.

- [tests/test_standardize.py:196](../../tests/test_standardize.py#L196): `test_apply_trim_removes_exactly_what_was_asked_for` computes its expectation with the implementation's own rounding expression, `int(round(x * SR))`, twice, in the same order as `apply_trim` (`standardize.py:192`). (mirror-tests)
  Any slicing function using the same rounding convention passes; if the impl switched `round` to `floor` the test would follow it instead of failing, and since `find_trim` produces the trim the test never pins what "exactly what was asked for" is in seconds. Suggested: hand-build the `Trim` and assert a literal sample count derived from the fixture's construction.

- [src/song_generator/standardize.py:452](../../src/song_generator/standardize.py#L452): `standardise_bank` coerces `source` at the top, wraps `out` inline as `Path(out)` three times (`:467`, `:468`, `:483`), then rebinds `out = Path(out)` at `:521`, while its sibling `check_tier` (`:571`) coerces both in one line at the top, which is also the `audio_io.py` house pattern. (stylistic-drift-within-file)
  Between lines 449 and 521 no single line tells the reader whether `out` is a `Path` or a `str`. Suggested: coerce both parameters beside line 452 and delete the inline wrappers and the late rebinding.

## Patterns observed but not in the checklist

- **One implicit-Optional annotation survives.** `pitchshift.py:48` declares
  `def fold_shift(semitones: float, cap: float = None) -> float:`. The
  `is None` guard at `:56` is load-bearing (the default is `None`), so this is
  not a defensive-check finding; the defect is the annotation. It is the sole
  implicit Optional left in `src/`, everywhere else uses `| None`. One-line
  fix: `cap: float | None = None`.
- **Near-misses worth recording so they are not re-litigated.**
  `mapping.py:998` guards `target is not None` where `target` looks
  impossible to be `None` until `config.py:827` documents that setting
  `MIMICRY = None` is a supported configuration. `config.py:901`
  `except ImportError: pass` is the documented optional
  `vocabulary_local.py` override. `flatten.py:117` `except OSError: pass`
  carries its reason on the `pass` line. All cleared.
- **Consistency findings that came back unusually strong**, for future runs:
  zero `os.path` usage (pathlib throughout), zero `isinstance` calls in
  `src/`, zero `typing` imports, one `.format()` call and it is the correct
  idiom (a module-level template constant), a uniform
  `build_parser`/`main`/`SystemExit` CLI convention across every tool
  module, and zero tests importing private helpers.
