## Findings by area

### Resource lifecycle

- [src/song_generator/audio_io.py:86](../../src/song_generator/audio_io.py#L86) [high]: `write_wav` calls `sf.write` directly on the destination path with no temp-file-plus-rename, so a crash or interruption mid-write leaves a truncated file at the final path.
- [src/song_generator/recut_bank.py:262](../../src/song_generator/recut_bank.py#L262) [high]: with `--overwrite`, `write_wav` overwrites clips already present in `--out` (a hand-curated, non-regenerable bank); since `write_wav` is not atomic, an interruption during the overwrite can leave a bank clip half-written with no recovery path.
- [src/song_generator/separate.py:64](../../src/song_generator/separate.py#L64) [medium]: `vocal.wav`/`instrumental.wav` cache files are written non-atomically and the cache-hit check at line 48 only tests `is_file()`, so a truncated file from an interrupted prior run is silently treated as valid cached audio on the next invocation.
- [src/song_generator/separate_hq.py:63](../../src/song_generator/separate_hq.py#L63) [medium]: inside the batch loop (lines 114-125), `separate_one` constructs a new `Separator` and calls `load_model` for every source file rather than loading the roformer model once and reusing it.
- [src/song_generator/batch.py:109](../../src/song_generator/batch.py#L109) [low]: each song calls `render_one` in-process, reloading separation/whisper models per song with no `torch.cuda.empty_cache()` or teardown between songs.

Clean: no `open()` outside `with`, no `subprocess.Popen`, no tempfile usage, no raw `sf.SoundFile` handles, no threads or timers. Clip renames in `label_words.py` and `set_aside.py` use `Path.rename`, atomic on the same filesystem.

### Data integrity

- [src/song_generator/label_words.py:158](../../src/song_generator/label_words.py#L158) [medium]: `read_all_rows` calls `float(parts[2])`/`float(parts[3])` on a hand-editable `labels.tsv` with no try/except, unlike `build_bank.read_labels` which wraps the identical conversion and raises a `LabelError` with file and line number; a hand-typed malformed timestamp crashes with a raw traceback instead of a diagnostic.
- [src/song_generator/arrange.py:489](../../src/song_generator/arrange.py#L489) [low]: `parse_text` silently falls back to `seed = 0` when the arrangement file's `# seed` header is not a valid int, while every other malformed field in the same function raises `ArrangementError`.
- [src/song_generator/audio_io.py:50](../../src/song_generator/audio_io.py#L50) [low]: `proc.stderr.decode(errors='replace')` here and at line 82 affects only the diagnostic text shown on ffmpeg failure, never audio or bank data; cosmetic.

Clean: bank-directory overwrite protection in `recut_bank.py` (clash refusal without `--overwrite`), `standardize.py` (`check_destination`/`write_derivative` refuse any output inside a source bank), `flatten.py` and `set_aside.py` (always check `target.exists()` before moving). Every text read/write passes `encoding="utf-8"` or `"utf-8-sig"`; no `errors="ignore"` anywhere. Sample rate is read from the file and resampled only on disagreement; all internal WAV I/O is float32 with no int16 conversion path. `build_bank.py` updating same-named clips in place on rebuild is documented, intentional behavior.

### Concurrency

- [src/song_generator/cli.py:215](../../src/song_generator/cli.py#L215) [medium]: `config.PLACE_BARE_SYLLABLES = True` is a module-level global mutated by `main()` when `--bare-syllables` is passed and never reset; `batch.py` calls this same `main()` repeatedly in one process, so the flag would leak into every subsequent song the moment it is exposed per-song or `cli.main()` is called twice in-process (latent today because `batch.py` does not forward the flag).
- [src/song_generator/recut_bank.py:225](../../src/song_generator/recut_bank.py#L225) [medium]: the `existing`/`clashes` collision guard is a one-time snapshot of `--out` taken before the write loop; the loop then writes via `write_wav` (which overwrites unconditionally) with no per-file re-check, so a clip added to the bank during the run is silently overwritten despite the guard.
- [src/song_generator/label_words.py:221](../../src/song_generator/label_words.py#L221) [low]: all five candidate-review tools (`label_words.py:221-236`, `precheck.py:257-259`, `hunt.py:191-193`, `flatten.py:102-108`, `set_aside.py:129-145`) use `target.exists()` followed by `path.rename(target)`; safe run one at a time, but two tools run concurrently against the same candidates folder can race between check and rename. One pattern, counted once.

Clean: no `threading`, `multiprocessing`, `concurrent.futures`, `asyncio`, or `queue` usage anywhere in `src/song_generator/`; the pipeline is genuinely single-threaded and single-process. Output naming in `cli.py` is deterministic from the song stem, and candidate filenames in `build_bank.py`/`extract_words.py`/`mine_words.py` derive from source and timestamp, not a next-free counter.

### Error paths

- [src/song_generator/separate_hq.py:71](../../src/song_generator/separate_hq.py#L71) [high]: `write_wav` can fail mid-write leaving a truncated `vocal_hq.wav`; both the per-call guard at line 57 (`if target.is_file(): return target`) and the batch skip-check at line 116 test only existence, never validity, so a corrupted HQ stem is treated as done on every future run with no warning.
- [src/song_generator/batch.py:137](../../src/song_generator/batch.py#L137) [medium]: `return 0 if done else 1` reports success as long as one song rendered; a batch where 19 of 20 songs fail still exits 0.
- [src/song_generator/mine_words.py:170](../../src/song_generator/mine_words.py#L170) [medium]: same pattern, `return 0 if summary.ok else 1` returns success if any single source mined.
- [src/song_generator/mine_words.py:85](../../src/song_generator/mine_words.py#L85) [medium]: the candidate-write loop (lines 78-84) has no try/finally; a failure partway leaves already-written candidate wavs on disk with no `labels.tsv`, an orphaned partial set until a rerun overwrites it.
- [src/song_generator/separate_hq.py:73](../../src/song_generator/separate_hq.py#L73) [low]: cleanup (`leftover.unlink()`/`out_dir.rmdir()`) runs unguarded after the target write succeeds; a locked leftover file (common on Windows) makes a successful separation count as `failed`.
- [src/song_generator/precheck.py:228](../../src/song_generator/precheck.py#L228) [low]: a failed Whisper batch is logged and skipped, and `main()` returns 0 at line 279 regardless of how many batches failed, so a mostly-failed transcription run reports success.
- [src/song_generator/precheck.py:259](../../src/song_generator/precheck.py#L259) [low]: `clip.path.rename(target)` is unguarded in the renaming loop; a mid-loop failure aborts with some clips renamed and others not (no truncation risk, per-file rename is atomic).

Assessed and cleared: `audio_io.py:48`/`:80` omit `check=True` but test `proc.returncode` immediately and raise `AudioError` with captured stderr. `hunt.py:172` and `batch.py:114` blind excepts are documented per-item resilience with the error printed and recorded. No bare `except: pass` anywhere under `src/song_generator/`.

### External boundaries

- [src/song_generator/build_bank.py:500](../../src/song_generator/build_bank.py#L500) [high]: `read_labels` validates the `word` column but never the `variant` column (line 88, `parts[1].strip()`); line 500 embeds it raw in `name = f"{stem}_{variant}.wav"` and line 510 writes `args.out / name` via `write_wav`, which creates parent directories. A `variant` containing `/`, `\`, or `..` in a hand-edited or tool-written `labels.tsv` walks the write out of the bank directory to an arbitrary relative path, silently. The input is the operator's own TSV, so exploitation is not the concern; a stray slash misdirecting a write, or a `..` landing on a curated clip, is.
- [src/song_generator/audio_io.py:48](../../src/song_generator/audio_io.py#L48) [medium]: the ffmpeg decode call has no `timeout=`; a stalled or malformed input hangs the pipeline indefinitely.
- [src/song_generator/audio_io.py:80](../../src/song_generator/audio_io.py#L80) [medium]: same missing `timeout=` on the ffmpeg encode call.

Clean: no `shell=True` and no string-built shell commands (both subprocess calls use list argv with the ffmpeg binary resolved via `shutil.which`); no `requests`/`urlopen` calls; no `pickle.loads` or `torch.load` in this codebase (model loading is inside demucs and audio-separator); no `zipfile`/`tarfile`; no `eval`/`exec`. `cli.py:115` builds the output path from the validated input file's own stem, so traversal via the input argument is not reachable. Candidate filenames in `extract_words.py:252` and `mine_words.py:80` come from internally computed values; `label_words.py:227` names come from vocabulary-matched words.
